## What the PDF promises and what to present

- **Pages 3–5:** The proposal shows on-device MobileNetV2/TFLite and a confidence-driven routing flow. The uploaded HTML calls cloud Gemini and has no trained model. This ZIP implements a server-side Gemini adapter plus manual and labelled sample paths. True offline inference requires a trained and evaluated model.
- **Pages 6–8:** The project proposes Flutter, Firebase, Maps API, messaging and a closed-loop dashboard. The HTML implements a static client and optional Supabase reads. This pilot delivers the closed-loop workflow with a browser UI and a local SQLite backend. Generic Maps links do not imply Maps Platform integration or navigation data partnerships.
- **Page 9:** ₹16,000 setup, monthly budget and per-ward break-even were proposal assumptions. The funded-ward setup plus twelve months of the stated ₹45,000 monthly figure totals ₹5.56 lakh before the separately presented USD component. Pricing, quotas, waste stream labels and the applicable legal language need fresh verification for a pilot agreement. The team's four scanner categories must not be presented as a regulatory compliance mapping. The proposed six-month plan also depends on verified facilities, a ward coordinator and a labelled dataset.
- **Page 10:** Cleaner localities and faster resolution are expected outcomes. Report the actual number of submitted cases, verification completion and elapsed closure time before citing impact.

## Implementation order

1. Remove frontend secrets from the new build. Establish a canonical database, authentication and private evidence access.
2. Exercise citizen report, admin assignment, officer cleanup and citizen verification. Test rejection paths and reopening.
3. Add scanner response validation, a manual path and transparent demo data. Join confirmed educational scans to a server ledger.
4. Add practical pilot operations including filters, CSV, recent activity, duplicate review and GPS plotting.
5. Before a supervised ward pilot, replace sample facilities with verified records, connect official ward boundaries, provision controlled staff accounts, test live Gemini on labelled photos and implement deployment controls described in the README.
6. Expand into QR-verified activities, municipal integrations, bilingual experiences and smart-city analytics after the core case data and permissions are validated.
